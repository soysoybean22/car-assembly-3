# PRD (Product Requirements Document)

## 프로젝트 개요

**프로젝트명:** car-assembly-3  
**언어:** Java  
**유형:** CLI 기반 자동차 조립 시뮬레이터

---

## 주요 기능

### 1. 단계별 부품 선택 흐름
사용자가 순서대로 4가지 부품을 선택하여 차량을 조립한다.

| 단계 | 선택 항목 | 선택지 |
|------|-----------|--------|
| 1 | 차량 타입 | Sedan / SUV / Truck |
| 2 | 엔진 | GM / TOYOTA / WIA / 고장난 엔진 |
| 3 | 제동장치 | MANDO / CONTINENTAL / BOSCH |
| 4 | 조향장치 | BOSCH / MOBIS |

- 각 단계에서 `0` 입력 시 이전 단계로 복귀 (CarType 단계 제외)
- `exit` 입력 시 프로그램 종료

### 2. 조립 완료 후 동작
모든 부품 선택이 완료되면 두 가지 액션이 가능하다.

- **RUN:** 선택한 부품 조합으로 차량을 실행. 유효 조합이면 부품 목록과 "자동차가 동작됩니다" 출력, 비유효 조합이면 오류 메시지 출력.
- **Test:** 부품 조합의 유효성을 검사하여 `PASS` 또는 `FAIL` + 실패 원인 출력.

### 3. 부품 호환성 규칙

| 차량 타입 | 제한 엔진/부품 | 사유 |
|-----------|---------------|------|
| Sedan | Continental 제동장치 사용 불가 | — |
| SUV | TOYOTA 엔진 사용 불가 | — |
| Truck | WIA 엔진 사용 불가 | — |
| Truck | MANDO 제동장치 사용 불가 | — |
| (공통) | BOSCH 제동장치 → 반드시 BOSCH 조향장치 | 제동/조향 제조사 일치 필요 |

### 4. 고장난 엔진
엔진 선택지에 "고장난 엔진(4번)" 존재. RUN 시도 시 부품 조합 유효 여부와 무관하게 "엔진이 고장나있습니다." 메시지를 출력하고 동작하지 않는다.

## 입력 처리

- 숫자 외 입력: "ERROR :: 숫자만 입력 가능" 출력 후 800ms 대기 후 재입력
- 범위 외 숫자: 각 단계별 범위 오류 메시지 출력 후 800ms 대기 후 재입력
- 유효 선택 후 800ms 딜레이 → 다음 화면으로 전환
- 화면 전환 시 ANSI 코드(`\033[H\033[2J`)로 터미널 클리어

---

## 현재 코드 특징 및 제약

- **단일 파일 구조:** 모든 로직이 `Assemble.java` 한 파일에 집중
- **정적(static) 상태 관리:** 선택값은 `static int[] stack[5]`에 저장 — 인스턴스 없이 전역 상태로 관리
- **JUnit 5 의존성 포함:** 현재 테스트 파일은 없으나 빌드 설정에 테스트 프레임워크 준비됨
- **호환성 검사 중복:** `isValidCheck()`와 `testProducedCar()` 두 곳에 동일 규칙이 중복 구현됨
- **ANSI 이스케이프 코드 사용:** Windows 환경에서 ANSI 미지원 터미널에서는 클리어가 동작하지 않을 수 있음
